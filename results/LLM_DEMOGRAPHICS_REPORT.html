Extension · Social Knowledge for Cross-Domain User Preference Modeling

Can demographics alone personalize an LLM's recommendations?

An LLM first infers a user's gender, age, ethnicity and education from the names of accounts they follow, then ranks less popular entities given only that inferred description. I compare this with ranking from the account names themselves, with social embeddings, and with non-personalized baselines, on the same 270 users.

1Method

Task and data. We use the less-popular-entity setting of the popularity-band extension. In each of nine categories (musical artists, news outlets, comedians, politicians, TV stations, actors, TV shows, sports teams and journalists), the candidates are the entities ranked 81–100 by Twitter follower count among the category's typed entities. Only entities with a SocialVec embedding are kept, leaving 18–20 per category. The users are the same stratified random sample used for the LLM experiments on this band: 30 users per category (270 in total), drawn with a fixed seed from the users sampled for that category who follow at least one candidate. The candidates a user follows are the relevant answers.

Stage 1: demographic inference. For each user, the LLM receives the names of the accounts listed in that user's k = 50 prompt. These are 50 accounts drawn at random from everything the user follows, after removing every listed entity of the target category, keeping only accounts with a known display name (28.7 names on average; minimum 3). The model is asked for a one- or two-sentence description stating the user's most likely gender, age, ethnicity and level of education. It is instructed to always guess from stereotypes about the typical audience of the accounts, never to state that the attributes cannot be determined, and not to mention interests or accounts, so that the description carries demographic information only. The prompt, in the dspy signature format of the original experiments:

Given the names of accounts that a Twitter user follows, write a short, concise description of the user that states their
most likely gender, age, ethnicity, and level of education (primary school, high school, higher education, etc.).
Deduce these attributes only from the names of the accounts they follow.
You must always guess the most likely value of all four attributes, based on stereotypes about the typical audience of
these accounts, even when the evidence is weak. Never answer that the attributes cannot be determined or that the
evidence is insufficient.
Describe only these four attributes: do not mention the user's interests or hobbies, and do not name any of the accounts.

Input  followed_accounts: Names of accounts the user follows
Output description: One or two sentences stating the user's most likely gender, age, ethnicity, and level of education

Stage 2: ranking from the description. The ranking prompt is the authors' personalized ranking prompt, with the list of followed accounts replaced by the Stage 1 description. As in the original experiments, the candidates are given as a JSON list of ids and display names, sorted by follower count, and the model must return a full ranking of the ids:

given the below Twitter user, for whom we provide a short demographic description, and a list of possible accounts to
recommend for the user to follow, create a prioritized recommendation list.
You must rank the entire list provided to you.
Try to deduce what you think the user might like based on their demographic description.
Return ONLY a valid list object with the ranked account twitter_user_id sorted by relevance (highest to lowest). Do not
include name or reasoning.

Inputs user_description, potential_accounts (JSON list of twitter_user_id and names)
Output ranked_ids

Evaluation. Each ranking is scored by average precision over the candidates the user follows, using the legacy scoring rule (relevant candidates missing from the response are skipped). MAP is the mean over users within a category, and overall MAP is the unweighted mean over the nine categories. All other methods are evaluated on the same users and candidates:

  • Non-personalized baselines: the expected AP of a random ranking; follower-count popularity; and the LLM with no user information.
  • LLM with account names: the LLM given the names of 12, 25 or 50 followed accounts.
  • SocialVec: cosine similarity to the average embedding of the same 12 or 25 accounts, or of all the user's followed entities.
Differences are tested with two-sided paired Wilcoxon signed-rank tests on per-user AP.

Implementation. GPT-6 Luna with reasoning effort low, called through dspy without caching, under a spending cap. Responses are cached locally per prompt version (this run uses version v3). dspy's end-of-output marker, which the model sometimes leaves inside the description, is removed before Stage 2. To measure how much demographic information each description carries, we label it complete if it states a value for all four attributes, declined if it states none, and partial otherwise. For complete and partial descriptions, we parse the stated values into the binary classes of SocialVec's trait classifiers, and compare them with those classifiers' predictions from the user's full embedding.

3The model often refused to infer demographics

Despite the instruction to always guess, the model declined to state any attribute for 198 of the 270 users (73%). Typical answers were "I can’t infer the user’s gender, age, ethnicity, or education level from the accounts they follow." It gave all four attributes for 67 users, and only some for 5, typically refusing ethnicity alone. Refusals occur in every category, from 18 to 26 of the 30 users, and are most frequent for politicians and journalists. The debugging runs did not reveal how common refusals are. Row 1864 complied, while row 1808, which had declined under the first prompt, declined again in the full run despite the stricter instruction.

When the model does describe the user, demographics carry real signal. For the 67 complete descriptions, the demographic ranking reaches 0.387, compared with 0.315 without user information (p = 0.02) and 0.326 for popularity. It is on par with the LLM given 12 account names (0.396) and with SocialVec on those same 12 accounts (0.394). For declined descriptions, the model ranks from an uninformative sentence, and the result is slightly but significantly worse than the no-information baseline (0.291 vs. 0.303, p = 0.02). The overall null result is therefore mostly a consequence of the refusals.

Caveat. With 67 users, the complete-description estimate is uncertain. These users were also not selected at random: the model may comply more readily when the accounts point clearly to a demographic group, which may also make the ranking easier.

For complete and partial descriptions, the stated value is mapped to the classifier's binary classes (descriptions stating another value, or an ambiguous one such as "20s" for age, are left out). The majority-class rate is the agreement a constant guess of SocialVec's most frequent class would achieve. Treat this as a rough check: the parsing is rule-based, and SocialVec's classifiers are themselves only estimates.

Where the model did state an attribute, its guesses agree with SocialVec's classifiers well beyond a constant guess for gender (80% vs. 65%) and ethnicity (97% vs. 79%). For education (72% vs. 69%) and age (93% vs. 90%), agreement is close to what always guessing the most common class would give, so the guesses add little there.

5Discussion and limitations

  • The main limitation is the model's own policy. GPT-6 Luna declined to infer demographics for 73% of users, even when told to rely on stereotypes. The experiment therefore measures a mix of demographic personalization and refusals. A cleaner test would reframe Stage 1, for example asking for the typical audience of the listed accounts rather than for attributes of an individual. Alternatively, it could supply the attributes from SocialVec's classifiers directly.
  • Demographics are a coarse summary of taste. Even when the description was complete, ranking from four attributes did not beat ranking from 12 account names, and it was far from SocialVec's full-profile embedding (0.451). The account names carry information beyond the demographic groups they imply.
  • Stereotype-based inference. The method asks a model to apply stereotypes about gender, age, ethnicity and education. The resulting descriptions are guesses about real people. They are stored outside the repository, and this page identifies users by internal row only. Conclusions about which groups like which entities should not be drawn from them.
  • Scale and noise. 30 users per category, one description and one ranking per user, at reasoning effort low. LLM outputs are not deterministic: repeated identical prompts change a user's AP by about 0.06 on average (see the candidate-order experiment).
