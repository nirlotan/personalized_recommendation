Extension · Social Knowledge for Cross-Domain User Preference Modeling

Can demographics alone personalize an LLM's recommendations?

GPT-4o infers a user's gender, age, ethnicity and education from the names of accounts they follow, and GPT-6 Luna then ranks less popular entities given only that inferred description. I compare this with ranking from the account names themselves, with social embeddings, and with non-personalized baselines, on the same 270 users, first with the candidates in follower-count order (Section 2) and then shuffled (Section 4).

1Method

Task and data. We use the less-popular-entity setting of the popularity-band extension. In each of nine categories (musical artists, news outlets, comedians, politicians, TV stations, actors, TV shows, sports teams and journalists), the candidates are the entities ranked 81–100 by Twitter follower count among the category's typed entities. Only entities with a SocialVec embedding are kept, leaving 18–20 per category. The users are the same stratified random sample used for the LLM experiments on this band: 30 users per category (270 in total), drawn with a fixed seed from the users sampled for that category who follow at least one candidate. The candidates a user follows are the relevant answers.

Stage 1: demographic inference (GPT-4o). For each user, GPT-4o (default sampling settings) receives the names of the accounts listed in that user's k = 50 prompt. These are 50 accounts drawn at random from everything the user follows, after removing every listed entity of the target category, keeping only accounts with a known display name (28.7 names on average; minimum 3). The model is asked for a one- or two-sentence description stating the user's most likely gender, age, ethnicity and level of education. It is instructed to always guess from stereotypes about the typical audience of the accounts, never to state that the attributes cannot be determined, and not to mention interests or accounts, so that the description carries demographic information only. The prompt, in the dspy signature format of the original experiments:

Given the names of accounts that a Twitter user follows, write a short, concise description of the user that states their
most likely gender, age, ethnicity, and level of education (primary school, high school, higher education, etc.).
Deduce these attributes only from the names of the accounts they follow.
You must always guess the most likely value of all four attributes, based on stereotypes about the typical audience of
these accounts, even when the evidence is weak. Never answer that the attributes cannot be determined or that the
evidence is insufficient.
Describe only these four attributes: do not mention the user's interests or hobbies, and do not name any of the accounts.

Input  followed_accounts: Names of accounts the user follows
Output description: One or two sentences stating the user's most likely gender, age, ethnicity, and level of education

Stage 2: ranking from the description (GPT-6 Luna). The ranking prompt is the authors' personalized ranking prompt, with the list of followed accounts replaced by the Stage 1 description. The candidates are given as a JSON list of ids and display names, and the model must return a full ranking of the ids. GPT-6 Luna runs at reasoning effort low, as in the other LLM experiments:

given the below Twitter user, for whom we provide a short demographic description, and a list of possible accounts to
recommend for the user to follow, create a prioritized recommendation list.
You must rank the entire list provided to you.
Try to deduce what you think the user might like based on their demographic description.
Return ONLY a valid list object with the ranked account twitter_user_id sorted by relevance (highest to lowest). Do not
include name or reasoning.

Inputs user_description, potential_accounts (JSON list of twitter_user_id and names)
Output ranked_ids

Candidate order. Section 2 lists the candidates sorted by follower count, as in the original experiments. Because an LLM partly copies the order it is given, Section 4 repeats Stage 2 with the candidates in one random order per user, shared by every condition of that user.

Evaluation. Each ranking is scored by average precision over the candidates the user follows, using the legacy scoring rule (relevant candidates missing from the response are skipped). MAP is the mean over users within a category, and overall MAP is the unweighted mean over the nine categories. All other methods are evaluated on the same users and candidates:

  • Non-personalized baselines: the expected AP of a random ranking; follower-count popularity; and the LLM with no user information.
  • LLM with account names: the LLM given the names of 12, 25 or 50 followed accounts.
  • SocialVec: cosine similarity to the average embedding of the same 12 or 25 accounts, or of all the user's followed entities.
Differences are tested with two-sided paired Wilcoxon signed-rank tests on per-user AP.

Description content. A description is complete if it states a value for all four attributes, declined if it states none, and partial otherwise. Since the prompt forbids mentioning interests, descriptions that name topics or interests (for example politics, sports, music or news) are flagged as naming interests: they carry information beyond demographics. Stated values are also parsed into the binary classes of SocialVec's trait classifiers and compared with those classifiers' predictions from the user's full embedding.

2Results with candidates in follower-count order

GPT-4o's descriptions give 0.352 MAP, compared with 0.276 for the LLM without user information and 0.295 for popularity. The gain is largest for descriptions that break the prompt by naming the user's interests (Section 3). Naming 12 followed accounts gives 0.402. In every table, the LLM without user information gets the candidates in a random order per user; with the candidates in follower-count order it scores 0.304, because it partly copies the presented order (Section 4). The rankings that use user information barely depend on the order, so they are compared with the shuffled baseline.

3What the descriptions contain

GPT-4o described every user: 268 descriptions state all four attributes, 2 only some (in wording the parser misses, such as "twenties" or "diverse ethnicity") and 0 none. But 60 of the 270 (22%) also name the user's interests, despite the instruction, for example "…with a higher education level, likely due to the interest in diverse media and sports analysts, personalities, and NFL-related accounts".

Leaked interests give most of the gain, but demographics alone also help. For the 60 users whose description names interests, the ranking reaches 0.508, far above the no-information baseline (0.280, p < 0.001). For the remaining 210 users, whose descriptions are demographics only, the score is 0.307 against 0.275 (p = 0.020): a smaller but significant gain. Against the baseline with sorted candidates, the demographics-only descriptions had looked no better (0.307 vs. 0.301, p = 0.783).

The stated value is mapped to the classifier's binary classes (descriptions stating another value, or an ambiguous one such as "20s" for age, are left out). The majority-class rate is the agreement a constant guess of SocialVec's most frequent class would achieve. Treat this as a rough check: the parsing is rule-based, and SocialVec's classifiers are themselves only estimates.

GPT-4o's guesses lean heavily toward the most common class: 264 of its education guesses are Degree, 237 of its age guesses are Over25, 244 of its ethnicity guesses are Caucasian. Agreement with SocialVec is therefore close to the majority-class rate, except for gender (72% vs. 64%).

4Shuffled candidates

With the candidates sorted by follower count, an LLM that partly follows the order it is given gets a popularity ranking for free, which can hide what a description adds. Here every user's candidates are put in one random order, used for all of that user's rankings: with no user information, from GPT-4o's description, and from the names of 12, 25 or 50 followed accounts (the prompts of Table 9 in results/results.html). Differences between them therefore come from the user information alone. All 270 users are included.

Overall MAP (mean over categories) with the candidates in random order. Highlighted bars: LLM rankings from GPT-4o's demographic description (orange) and from the names of followed accounts (green).

Findings.

  • Shuffling removes the order advantage of the no-information ranking. It drops from 0.304 (popularity-sorted candidates) to 0.276 (p = 0.003). The ranking from GPT-4o's descriptions barely changes (0.352 → 0.355, p = 0.69), and neither do the name-based rankings (0.402 → 0.397, 0.421 → 0.398 and 0.501 → 0.486 for 12, 25 and 50 names, p ≥ 0.15).
  • With a fair baseline, demographic descriptions help. GPT-4o's descriptions score 0.355 against 0.276 without user information (p < 0.001).
  • The gain does not depend on leaked interests. Demographics-only descriptions also beat the no-information ranking (0.328 vs. 0.275, p < 0.001), as they do in Section 3.
  • Account names give larger gains than demographics. Ranking from 12 followed account names scores 0.397, above GPT-4o's descriptions (p = 0.034). 25 names add nothing over 12 (p = 0.77); 50 names do (0.486, p < 0.001).
  • Social embeddings vs. the LLM. SocialVec, using all of the user's followed entities, scores 0.451.
    • Demographics: GPT-4o's descriptions stay below it (p < 0.001).
    • 50 names: the LLM with 50 account names scores above it (p = 0.021).
    • Same accounts: SocialVec using only the same 12 or 25 accounts scores 0.362 and 0.365, below the LLM's 0.397 and 0.398 (p = 0.027 and p = 0.022; means over users).

6Discussion and limitations

  • The model does not always follow the instruction. GPT-4o described every user, but in 22% of cases it also named the user's interests. The clean condition is the demographics-only subset. A stricter test would filter or rewrite descriptions to a fixed format (e.g. four labelled fields), or supply the attributes from SocialVec's classifiers directly.
  • The candidate order matters for this comparison. With popularity-sorted candidates, the no-information ranking partly copies the presented order, and demographics-only descriptions looked no better than it. With shuffled candidates, they give a significant gain. Comparisons with a non-personalized LLM ranking should therefore use randomized candidate orders.
  • Demographics are a coarse summary of taste. Ranking from four attributes scores below ranking from 12 account names and below SocialVec's full-profile embedding. The account names carry information beyond the demographic groups they imply.
  • Stereotype-based inference. The method asks a model to apply stereotypes about gender, age, ethnicity and education. The resulting descriptions are guesses about real people. They are stored outside the repository, and this page identifies users by internal row only. Conclusions about which groups like which entities should not be drawn from them.
  • Scale and noise. 30 users per category, one description and one ranking per user. LLM outputs are not deterministic: repeated identical prompts change a user's AP by about 0.06 on average (see the candidate-order experiment). Stage 1 with GPT-4o cost $0.39 for 270 descriptions.
